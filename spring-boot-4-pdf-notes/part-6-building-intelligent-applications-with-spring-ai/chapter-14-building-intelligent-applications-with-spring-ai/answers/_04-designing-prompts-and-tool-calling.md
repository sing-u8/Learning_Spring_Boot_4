## Q1. "이 코드 리뷰해 줘"와 "지금 재고 몇 개야"

| 질문 | **축** | **이유** |
|---|---|---|
| **"이 코드 리뷰해 줘"** | **축 1 — 프롬프트 엔지니어링** | **필요한 정보가 이미 요청 안에 있다.** 문제는 **어떻게 조립해 지시할 것인가** |
| **"지금 재고 몇 개야"** | **축 2 — 툴 콜링** | **답이 우리 데이터베이스에 있다.** **아무리 prompt를 잘 써도 없는 정보가 생기지는 않는다** |

> **같은 "동적"이라는 말이지만 동적 값과 동적 지식은 다른 기계가 필요하다.**

**축 1이 푸는 것**: **요청의 일부가 사용자 문장이 아니라 애플리케이션의 상태**일 때. 코드 리뷰는 **"언어는 Java, 검사 항목은 버그·보안·성능 세 가지, 검사 대상 코드는 이것"**이 필요하다.

**문자열 연결로 만들기 시작하면**: **문구를 고치려면 Java 파일을 열어야 하고, 문구를 검토할 사람(기획·법무·도메인 전문가)이 소스를 읽어야 하고, 큰따옴표와 줄바꿈 이스케이프가 문구보다 눈에 띈다.**

**축 2가 푸는 것**: **문구의 문제가 아니라 접근의 문제.**

**요점은 툴 콜링의 방향이다** — **우리가 "가격 질문이면 `getProductPrice`를 불러라"라고 분기하는 게 아니라, 도구 목록과 설명을 넘겨주면 model이 필요할 때 스스로 고른다.**

**RAG는 어느 축인가**(§5): **축 2에 가깝지만 결이 다르다.** **툴 콜링은 구조화된 실시간 값(가격·재고·시각)을, RAG는 대량의 비정형 지식(문서·정책·계약)**을 가져온다.

## Q2. 시스템 프롬프트가 매 요청 다시 전송되는 이유

**model이 기억하지 않기 때문이다.**

> **사람은 지침서를 읽고 기억한다. model은 매 요청 지침서를 처음부터 다시 받는다 — 시스템 메시지를 매번 붙여 보내는 이유가 그것이다.**

**LLM 호출은 상태가 없다** — 각 요청이 **독립**이고, **이전 요청에서 무엇을 말했는지 model 쪽에 남지 않는다.**

**결과 둘**:
- **`defaultSystem(...)`이 매 요청에 붙는다** — [[02-building-llm-integrations-with-chatclient]]의 그 설정
- **대화 이력도 매번 다시 보내야 한다** — [[05d-conversation-memory-with-chat-memory-advisor]]의 chat memory가 그 일을 한다

**비용으로 이어진다** — 시스템 메시지가 길면 **모든 요청이 그만큼 비싸진다.** [[01-introducing-llms-and-spring-ai]]의 컨텍스트 윈도 예산도 그만큼 줄어든다.

**비유의 나머지 깨짐**: **사람은 지침서와 상충하는 요청을 받으면 의심하지만, model은 그럴듯한 지시면 따라갈 수 있다.** 그 취약점이 **[[07d-security-best-practices-for-ai-applications]]의 프롬프트 인젝션**이다.

## Q3. 도구 설명이 prompt 설계의 일부인 이유

**model이 그 설명만 보고 도구를 고르기 때문이다.**

> **도구 설명 자체가 prompt의 일부이고, model은 그 설명을 읽고 도구를 고른다. 설명이 모호하면 도구를 안 부르거나 엉뚱한 것을 부른다.**

**"prompt를 잘 쓰면 도구 없이도 된다"도 틀리고 "도구만 잘 붙이면 prompt는 대충"도 틀리다**(§5) — **없는 정보는 문장력으로 만들어지지 않지만, 도구를 고르는 것도 결국 언어 이해**다.

**두 축을 섞은 실제 assistant**:
```
시스템 프롬프트: "너는 TechStore 상담원이고 TechStore 관련 질문에만 답한다"  ← 범위
도구:            실제 가격을 물어다 준다                                    ← 지식
```

**하나가 빠지면**:
| 빠진 것 | **증상** |
|---|---|
| **프롬프트 설계** | **도구는 있는데 model이 엉뚱한 어조로, 형식 없이, 범위 밖 질문까지 답한다** |
| **툴 콜링** | **말투는 완벽한데 가격을 지어낸다** |

**비유로 보면** 새 직원 교육 — **프롬프트 엔지니어링은 업무 지침서, 툴 콜링은 사내 시스템 계정.** **지침서만 주면 성실하지만 아무것도 조회하지 못하고, 계정만 주면 조회는 하는데 응대 규칙을 모른다.**

**실무적 귀결**: **도구가 안 불렸을 때 고칠 곳은 분기 코드가 아니라 `description`**이다([[04b-tool-calling]]).
